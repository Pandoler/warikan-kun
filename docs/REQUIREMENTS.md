# 割り勘アプリ 要件定義書

## 1. 概要

飲み会・食事会の会計を、**均等割り**または**傾斜を付けた割り勘**で計算できる Web アプリ。
その場（会計時）でサッと使えることを最優先とし、サーバー・アカウント登録・データ保存は不要とする。

## 2. 決定事項サマリー

| 項目 | 決定内容 |
|---|---|
| アプリ形態 | Web アプリ（静的サイト、スマホブラウザ最適化） |
| 利用シーン | 1 回の飲み会・食事会（単一の合計金額を精算） |
| 傾斜方式 | 役割プリセットによる倍率提案 ＋ 金額直接指定 ＋ 均等/傾斜割りの組み合わせ |
| 端数処理 | 丸め単位を選択可能（1 円 / 10 円 / 100 円 / 500 円） |
| 丸め差額 | 処理方法を選択可能（切り上げて集める / 切り捨てて集める）。生じた余り・不足金はメンバーごとに金額を指定して割り振る |
| データ保存 | 不要（ブラウザ内で完結、リロードで消えてよい） |
| 技術スタック | React + Vite + TypeScript |

## 3. 機能要件

### 3.1 基本フロー

1. **合計金額の入力** — 会計の総額を入力する
2. **メンバーの追加** — 名前を入力して人数分追加する（名前省略時は「メンバー1」等の自動命名）
   - 初期表示は **5 名**（飲み会の標準的な人数）。過不足は追加・削除で調整する
3. **各メンバーの支払い方法の設定** — 以下のいずれかを選択
   - **均等/傾斜割り**（デフォルト、倍率 1.0）
   - **役割プリセット** — 選ぶと推奨倍率が自動設定され、手動で微調整も可能
   - **金額直接指定** — 「部長は 10,000 円」のように固定額を設定
4. **端数設定** — 丸め単位と差額の引き受け先を選択
5. **結果表示** — 各メンバーの支払額・合計・差額の内訳を表示

### 3.2 役割プリセット（倍率提案）

| 役割 | 推奨倍率 |
|---|---|
| 上司・目上 | 1.5x |
| 先輩 | 1.2x |
| 同僚（標準） | 1.0x |
| 後輩 | 0.8x |
| 学生・新人 | 0.5x |
| 無料 | 0x |

- プリセット選択後も倍率は手動で自由に上書きできる
- 倍率 0 は「支払いなし」を意味する

### 3.3 金額直接指定との組み合わせ

- 固定額メンバーの合計を総額から差し引き、**残額**を倍率メンバーで按分する
- 例: 総額 30,000 円、部長が固定 10,000 円 → 残り 20,000 円を残りのメンバーの倍率比で分配

### 3.4 端数処理

- 丸め単位: **1 円（丸めなし） / 10 円 / 100 円 / 500 円**
- 丸めによって生じる合計との差額の処理方法:
  1. **切り上げて集める** — 全員切り上げで集金し、生じた**余り（おつり）**を表示する
  2. **切り捨てて集める** — 全員切り捨てで集金し、生じた**不足金**を表示する

#### 余り・不足金の割り振り

- 余り・不足金は、**メンバーごとに金額を手入力**して任意のメンバー（複数可、固定額のメンバーも可）に割り振る
  - 切り上げ: 入力した額だけ、そのメンバーの支払額を**減額**する（おつりを受け取る）
  - 切り捨て: 入力した額だけ、そのメンバーの支払額に**上乗せ**する（不足金を負担する）
- 余り・不足金の額と「未割り振り ○円 / 割り振り済み ✓ / ○円 多すぎます」を常に表示する
- **切り上げは割り振らなくてもよい**。割り振らなかった分は余りとして残す（幹事の取り分・次回に回す運用）
- **切り捨ては全額を割り振る必要がある**。不足のままでは会計できないため、未割り振りがあれば警告する
- 割り振りすぎた場合は警告する（計算結果はそのまま表示する）
- 処理方法を切り替えると、割り振りはリセットする（減額と上乗せで意味が逆になるため）
- 割り振りを受けないメンバーの支払額は、切り上げなら理論値以上、切り捨てなら理論値以下になる

> 変更履歴: 以前は「四捨五入して指定メンバーが吸収」「切り捨てて不足分を指定メンバー 1 人が負担」を提供していた。
> 前者は後者と結果が一致する場面が多く紛らわしいため廃止し、後者は 1 人への自動割り当てから
> 切り上げと同じ手入力の割り振りに統一した。

#### 端数が出ない場合の扱い

全メンバーの理論値がちょうど丸め単位の倍数になる場合（例: 総額 30,000 円を 5 人で均等割り・100 円単位）は、
どの処理方法を選んでも支払額が変わらない。この場合は **差額の処理を選択させず**、
「ちょうど割り切れるため、差額の処理は不要です」と表示する。

### 3.5 結果表示

- 各メンバーの名前・支払額・（適用された倍率 or 固定額の別）
- 割り振りを受けたメンバーには増減（「おつり −○円」「不足分 +○円」）を表示する
- 集金合計と総額、差額（余り／不足）の内訳
- 結果テキストのコピー機能（LINE 等に貼り付けて共有できるプレーンテキスト）

## 4. 非機能要件

- **スマホファースト UI** — 飲み会の場でスマホから操作する前提
- **サーバー不要** — 静的サイトとしてホスティング可能（GitHub Pages 等）
- **オフライン計算** — 一度読み込めばネットワークなしで計算可能
- **即時再計算** — 入力変更のたびに結果をリアルタイム更新

## 5. スコープ外（今回はやらないこと）

- 複数の支払い（立て替え）の精算（旅行モード）
- データの永続化・履歴
- ユーザーアカウント・ログイン
- URL やサーバー経由でのデータ共有（結果のテキストコピーで代替）
- 品目ベース（飲んだ・食べた別）の傾斜
